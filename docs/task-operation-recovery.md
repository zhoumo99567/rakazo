# 任务汇报、长命令和恢复

## 三种独立状态

- 执行器心跳来自 Run lease。`execution.heartbeat` 为 current、expired 或 inactive，只说明执行器租约状态，不能证明命令或业务有进展。
- 操作状态来自计算机内的持久操作记录。`execution.operations` 提供 running、completed、timed_out、cancelled、unknown，以及操作开始、独立截止时间、最近查询时间和退出码。长时间没有新查询的运行状态按 unknown 返回。
- 业务进展来自 Bot 明确提交的 status 汇报。`lastProgressAt` 不因心跳、输出流、查询或无变化汇报推进；`lastReportedAt` 单独记录汇报时间。问题消息也不会自动推进业务进展。

`tasks.list` 与 `task_status` 共用这些字段。任务时间线已有的最新汇报仍是实际业务汇报，不会用心跳或日志伪造进度。

## 事件汇报与软巡检

Bot 在阶段变化、阻塞和结果产生时汇报。既有汇报间隔是软巡检周期：到期在安全边界提醒，持续未汇报时给父任务一条去重的观察通知。提醒不取消、不失败、不重启任务，也不要求中断健康操作来凑汇报。

人工输入、接管和等待子任务仍按现有规则暂停汇报计时。取消必须来自明确取消操作；命令执行时限与汇报间隔互不影响。

## 长命令

`shell.timeout_ms` 是单条命令的独立执行时限，范围为 1–3,600,000 毫秒。例如预计需要 30 分钟的命令可设置 2,100,000，留出正常收尾时间。省略时沿用现有部署的命令默认值（默认 5 分钟）；不会因为汇报逾期缩短它。

无输出的命令也会及时返回“仍在运行”，使运行时可以接收指令；完成后再交付真实退出码。流没有退出事件就断开时视为结果未确认，不能当作退出码 0。

Docker 计算机支持持久命令操作：

1. 先在 ExternalEffect 中保存操作标识、计算机引用，再请求启动。
2. 计算机内的独立进程以操作标识去重，记录进程身份、时限及有界输出；与 Worker 和 HTTP 连接分离。
3. 查询只读已有操作，不创建新命令。Worker 或 supervisor 重启后可以重新查询同一操作。
4. 操作自身执行到时限才终止其进程组，返回 124；显式操作取消返回 130。正常结束保存真实退出码。状态查询或汇报逾期不会杀进程。
5. Runner 消失、计算机不可达或记录缺失时保持 unknown；不能从“没有收到结果”推断“没有执行”。

状态保存在计算机 home 的应用状态目录中。输出保留有界尾部，完整大日志应由命令写入工作文件。计算机文件系统丢失或 runner 死亡时不能承诺自动还原执行状态；此时保持待核实，不自动重放。

能力由可选的、提供商无关的 `commandOperation` 接口表达。当前 Docker 实现该能力；其他提供商继续使用原有命令执行与不确定副作用防重机制，支持独立时限，但不承诺跨 Worker 重启恢复其后台命令。不会静默把不支持的提供商当成可持久恢复。

## 恢复与结果交付

恢复中的执行器先查询已持久化的操作，再打开模型继续工作。运行中的操作继续等待原结果；状态未知时保留任务，不重复启动操作。Run 心跳继续独立续租，用户仍可取消任务。

结果及一条带稳定去重标识的系统结果消息在同一个数据库事务提交。事务先确认当前 Run fence，旧 Worker 不能覆盖新 Worker 的结果。写入失败则重查原操作并重试提交，不能把数据库故障包装成命令成功或命令失败。重复完成通知只生成一条结果消息。

业务子任务结束仍走现有父子任务 outbox：使用稳定 deliveryKey 回传 outcome，父任务恢复与结果提交分离。不会把命令成功直接等同于业务任务验收通过。

本改造不新增数据库表或迁移，不改变已有任务标识、Space 权限或群聊任务关系。

## 验证边界

- 使用虚拟时钟覆盖 30 分钟无输出命令、5 分钟周期软巡检，以及结束后的单次父任务结果交付。
- Linux 实际进程覆盖并发启动去重、重新连接查询、结果保留、独立超时、显式取消和 runner 失联。
- PostgreSQL 覆盖结果/消息原子提交、注入消息写入失败后的重试、并发去重、旧 fence 拒绝与三个状态维度分离。
- 执行器回归覆盖恢复前查询操作，以及模型更换工具调用 ID 后仍复用已完成结果。
